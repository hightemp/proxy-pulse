# Proxy Pulse — план реализации

Дата: 2026-09-05. Основание: [PRD.md](PRD.md), версия 1.0.

Этот файл и PRD.md — на русском. Приложение, исходный код, комментарии, тестовые названия, сообщения, README, ADR и отчёты о проверках — на английском.

## 1. Правила выполнения

- `[ ]` — задача не завершена; `[x]` — выполнены результат и критерии приёмки, сохранено подтверждение.
- При начале задачи добавить `Статус: in_progress`; при внешней блокировке — `Статус: blocked` с конкретной причиной. Незавершённую задачу не отмечать выполненной.
- Зависимости перечислены явно. Независимые ветки можно разрабатывать независимо; интеграционные этапы закрываются после всех зависимостей.
- Spike — ограниченное техническое исследование с работающим минимальным примером и письменным решением. Не считать поддержку протокола доказанной по описанию библиотеки.
- Сетевые тесты используют локальные управляемые прокси и синтетические реквизиты. Проверки публичного сервиса не заменяют детерминированные тесты и не запускаются в CI автоматически.
- Готовность каждой ОС подтверждается отдельно. Невозможность проверить Windows/macOS оставляет соответствующие задачи открытыми.
- Изменение обязательного объёма синхронно отражается в обоих документах. Реальные реквизиты прокси и локальные инфраструктурные заметки не добавляются в репозиторий.

- Готово, когда: есть конкретная матрица `OS / architecture / build / GUI verification / packaging`; недоступные среды явно помечены, README может воспроизвести установку инструментов.

### [ ] T-002. Проверить сетевой стек на полном наборе протоколов

- Зависимости: T-001. Требования: FR-05–FR-09, PRD §9.1; AC-03, AC-05–AC-07, AC-12.

- Готово, когда: выбран стек, доказана вся обязательная матрица локальными запросами; проверены trust store, отключение env/system proxy и `NO_PROXY`, состав нативных зависимостей, лицензии и упаковка. Для пробела есть реализуемый адаптер, а не скрытое исключение из MVP.

### [ ] T-003. Зафиксировать проверочные профили и классификацию

- Выполнить: проверить опубликованный формат ipify и отдельно выполнить разрешённый smoke-запрос на этапе реализации; определить валидатор IP/статуса/тела, приоритет ошибок, порог приостановки endpoint и вложенные бюджеты.

**Выход этапа:** реализация опирается на проверенный стек и конкретные контракты; ограничения не скрыты.

## 5. Этап 2 — импорт и форматы

### [ ] T-008. Реализовать текстовый и URI-парсер

- Зависимости: T-006. Требования: FR-02, FR-03; AC-01, AC-02, AC-07.
- Результат: F-01–F-18 и явно выбираемый F-21, включая IPv6, DNS-имена, IDNA, протокол в начале/конце и percent-encoding URI.
- Готово, когда: парсер возвращает запись либо конкретную ошибку с номером строки; требует порт, не угадывает обратный порядок и `socks`, не заменяет отсутствие схемы HTTP, не теряет символы реквизитов, соблюдает лимиты и правила пустых значений.

### [ ] T-009. Реализовать CSV/TSV и сопоставление колонок

- Зависимости: T-006, T-008. Требования: FR-01–FR-03, F-19–F-22; AC-02.
- Результат: запятая, точка с запятой, табуляция, кавычки, заголовки-алиасы, колонка `proxy`, `label` и ручной выбор схемы.
- Готово, когда: предпросмотр объясняет выбранные delimiter/header/mapping; пользователь может их изменить; лишние колонки игнорируются явно, ошибки кавычек и multiline-полей не дают повреждённых реквизитов.

### [ ] T-010. Реализовать нормализацию, дубликаты и версии записей

- Зависимости: T-008, T-009. Требования: FR-04; AC-13.
- Результат: общий ключ дубликата, `Skip duplicates` / `Keep duplicates`, Append/Replace и редактирование записи.
- Готово, когда: разные пароли, Auto/explicit и DNS mode не объединяются; сверяются новые и уже добавленные строки; сохраняются source metadata; редактирование сбрасывает результат и подсказку Auto.

### [ ] T-011. Собрать UI импорта

- Зависимости: T-007–T-010. Требования: FR-01, FR-10; US-01, US-06.
- Результат: вставка текста/clipboard, выбор файлов, drag-and-drop, предпросмотр, счётчики, редактирование ошибок и `Import valid`.
- Готово, когда: смешанный список импортируется без ручной переписи; ошибки одной строки не блокируют корректные, пароли скрыты, превышение размера не приводит к частичному добавлению. Ошибки чтения/кодировки и отмена диалога обрабатываются в UI.

### [ ] T-012. Создать проверочный корпус форматов

- Зависимости: T-008–T-010. Требования: AC-01, AC-02, AC-07, AC-13; NFR-08.
- Результат: табличные тесты положительных и отрицательных случаев F-01–F-22, property-based проверки URI round trip, синтетические файлы UTF-8/BOM/LF/CRLF.
- Готово, когда: покрыты IPv6 без скобок, порты 0/65536/нечисловые, `%`/`+`/`@`/`:`, пустые поля, неверные схемы, конфликты, комментарии, числовые логины/пароли, CSV-кавычки, управляющие символы, ограничения длины и дубликаты. Ошибочные входы не вызывают panic.

**Выход этапа:** список можно безопасно и предсказуемо загрузить; все форматы имеют исполняемые примеры.

## 6. Этап 3 — сетевое ядро

### [ ] T-013. Создать локальные сетевые фикстуры

- Зависимости: T-002, T-005. Требования: NFR-08; AC-03, AC-05–AC-08, AC-12.
- Результат: управляемые HTTP/HTTPS/SOCKS4/SOCKS4a/SOCKS5-прокси, HTTP/HTTPS назначения, тестовый CA и режимы отказов; команда запуска/очистки.
- Готово, когда: воспроизводятся valid/invalid auth, USERID, неподдерживаемый метод, broken CONNECT, неверный TLS, 403/407/429/5xx, redirect, oversized/invalid body, зависание, reset и непрокси TCP/HTTP-сервер. Не требуется доступ к публичным прокси или реальным секретам.

### [ ] T-014. Реализовать HTTP и HTTPS-прокси

- Зависимости: T-002, T-006, T-013. Требования: FR-05, FR-07, FR-08; AC-03, AC-05, AC-06, AC-12.
- Результат: HTTP forward для HTTP-профиля, CONNECT для HTTPS-профиля, TLS к HTTPS-прокси, Basic/no-auth и предметные ошибки.
- Готово, когда: запрос действительно выходит через фикстуру; внешний и внутренний TLS проверяются независимо; 407 отделён от 401/403 назначения; env/system proxy и NO_PROXY не меняют маршрут. Plaintext не включается после ошибки явно заданного HTTPS; успех без использования реквизитов отмечен `Not required`.

### [ ] T-015. Реализовать SOCKS4, SOCKS4a и SOCKS5

- Зависимости: T-002, T-006, T-013. Требования: FR-03, FR-05, FR-07, FR-08; AC-03, AC-05, AC-07.
- Результат: CONNECT для SOCKS4/4a, USERID, SOCKS5 no-auth/username-password, local/remote DNS и поддерживаемые адресные семейства.
- Готово, когда: локальный наблюдаемый DNS-тест отличает `socks5` от `socks5h`; пароли SOCKS4 не игнорируются; длина SOCKS5 проверяется в байтах; IPv6 проверен отдельно для адреса прокси и назначения; неподдерживаемый метод имеет свой код. Переданный USERID и проверенная username/password-авторизация не смешиваются.

### [ ] T-016. Реализовать профили и валидатор ответа

- Зависимости: T-003, T-014, T-015. Требования: FR-07, FR-08; AC-06, AC-08.
- Результат: default HTTPS IP check, custom HTTP/HTTPS URL, ожидаемые коды/строка, optional fallback endpoint, IP validator и измерения времени.
- Готово, когда: успех требует корректного полного ответа; IP отсутствует там, где его не измеряли; профиль/URL и длительности сохраняются; redirect не выполняется; лимиты заголовков/декодированного тела соблюдаются; резервный запрос использует тот же прокси и оставшийся бюджет.

### [ ] T-017. Реализовать Auto и агрегацию результатов

- Зависимости: T-014–T-016. Требования: FR-06, FR-08; AC-03, AC-04, AC-08.
- Результат: последовательные кандидаты, отдельные соединения, пропуск несовместимых вариантов, история попыток и первый полный успех.
- Готово, когда: выполнен порядок FR-06; явная схема не меняется; открытый порт/TLS/случайный HTTP 200 не дают `Working`; неизвестный/незавершённый перебор получает правильный код; сильная причина не затёрта поздним таймаутом; повторный Auto проверяет прежний режим заново.

### [ ] T-018. Реализовать очередь, отмену, сроки и повторы

- Зависимости: T-006, T-017. Требования: FR-09; NFR-03, NFR-04; AC-09.
- Результат: ограниченная параллельность, глобальная частота попыток, вложенные deadlines, cancellation и допустимые retries.
- Готово, когда: реально одновременно работает не больше заданного числа попыток; очередь и rate-limit учитываются по PRD; Stop закрывает операции в срок; повтор auth/TLS ошибок отсутствует; можно начать новый запуск без влияния поздних событий предыдущего. Для отмены не остаётся необратимо зависших фоновых потоков.

### [ ] T-019. Обработать общие сбои проверочного сервиса

- Зависимости: T-016–T-018. Требования: FR-08; AC-08.
- Результат: локализованная диагностика стадий, `Inconclusive`, счётчик ответов endpoint, приостановка новых запросов по порогу и понятное действие в UI-контракте.
- Готово, когда: 5+ ответов 429/5xx при доле 80% в заданном окне включают предусмотренное поведение; успешный fallback учитывается; уже готовые результаты не переписываются. Общая ошибка не превращается в массовый `Failed`, прямой контрольный запрос не добавляется.

### [ ] T-020. Проверить сетевое ядро в интеграции

- Зависимости: T-013–T-019. Требования: AC-03–AC-09, AC-12; NFR-03, NFR-04, NFR-08.
- Результат: интеграционная матрица и английский отчёт с командами, платформой и ожидаемыми/фактическими результатами.
- Готово, когда: пройдены все протоколы с/без auth, explicit/Auto, оба TLS-слоя, DNS, IPv6, fallback, timeout, rate limit, cancellation и ошибки endpoint. Наблюдением соединений доказано отсутствие прямого пути к назначению, в том числе при установленном NO_PROXY.

**Выход этапа:** `Working` подтверждается полным запросом, а отрицательные результаты имеют проверяемое объяснение.

## 7. Этап 4 — GUI и управление проверкой

### [ ] T-021. Собрать основное окно и таблицу

- Зависимости: T-004, T-006, T-011. Требования: FR-10; NFR-02; AC-16.

- Готово, когда: столбцы и состояния соответствуют PRD; пустые latency сортируются в конце; большие списки не создают DOM на каждую строку; полные значения доступны без раскрытия паролей по умолчанию; клавиатура и доступные подписи работают.

### [ ] T-022. Связать GUI с запуском и результатами

- Готово, когда: счётчики сходятся с состояниями строк, готовые результаты доступны до конца запуска, UI реагирует во время нагрузки; profile snapshot и stale-by-profile видны, поздние события не меняют новую проверку.

### [ ] T-023. Добавить настройки и завершение сессии

- Готово, когда: запуск использует снимок настроек; закрытие активной проверки предлагает остановку; непустая сессия предлагает сохранить данные; ошибка/отмена сохранения оставляет окно открытым. Пользовательский URL не сохраняется автоматически на диск.

## 8. Этап 5 — копирование и экспорт

### [ ] T-024. Реализовать области экспорта и снимок данных

- Зависимости: T-006, T-021. Требования: FR-08, FR-11; AC-10.
- Результат: единый селектор Working/Failed/Checked/Inconclusive/Selected/Filtered/All, стабильный порядок и snapshot на момент действия.
- Готово, когда: `Checked` имеет точный состав PRD; Working/Failed не сужаются UI-фильтром; Selected и Filtered различаются; текущая проверка не меняет уже выбранный снимок. Пустая область и Invalid обрабатываются явно.

### [ ] T-025. Реализовать сериализаторы TXT/CSV/JSON

- Зависимости: T-008–T-010, T-024. Требования: FR-11; AC-07, AC-10, AC-11.
- Результат: URI, исходные строки, компактный формат, CSV/JSON отчёт, credentials toggle и JSON schema version.
- Готово, когда: URI/JSON сохраняют точные данные; IPv6, пустой пароль и DNS mode не теряются; Auto без успеха не получает выдуманную схему; непредставимый компактный формат не пропускает строки. Исходные таблицы сохраняют схему либо явно требуют другого формата; CSV-формулы обезвреживаются только в отчёте.

### [ ] T-026. Подключить clipboard и атомарное сохранение

- Зависимости: T-007, T-025. Требования: FR-11; AC-11.
- Результат: один сформированный payload для clipboard/file, системный диалог и надёжная запись с обработкой ошибок.
- Готово, когда: отмена не создаёт пустой файл; перезапись обрабатывается явно; отказ в доступе/нехватка места не уничтожает старый файл; успех показывается после завершения. После экспорта доступны точные количество и формат.

### [ ] T-027. Добавить быстрые действия и предпросмотр экспорта

- Зависимости: T-022, T-024–T-026. Требования: FR-10, FR-11; US-04, US-05; AC-10, AC-11.
- Результат: Copy/Save working, Copy/Save failed, меню остальных групп/форматов, настройки реквизитов и понятные причины недоступного формата.
- Готово, когда: быстрые кнопки используют заданные в PRD форматы; пользователь видит количество и включение паролей; неподдерживаемые строки не теряются. Save and quit из T-023 использует тот же завершённый механизм.

### [ ] T-028. Проверить экспорт и повторный импорт

- Зависимости: T-012, T-025–T-027. Требования: AC-07, AC-10, AC-11; NFR-06.
- Результат: проверки точного состава групп, URI round trip, исходных файлов, структуры JSON/CSV и ошибок системных операций.
- Готово, когда: корректно обработаны спецсимволы/IPv6/Unicode, пустые/отсутствующие реквизиты, неизвестная схема, смешанные источники, snapshot при проверке, CSV formula prefixes и отказ записи. Нет масок, ошибочно экспортированных как пароль; CSV-отчёт явно не обещает точный round trip.

**Выход этапа:** основной сценарий «импорт → проверка → рабочие/нерабочие в clipboard/файл» полностью доступен в GUI.

## 9. Этап 6 — качество и выпуск

### [ ] T-029. Провести сквозную приёмку на Linux

- Зависимости: T-020, T-023, T-027, T-028. Требования: AC-01–AC-13, AC-16; NFR-07.
- Результат: английский GUI-отчёт с ОС/окружением, сборкой и результатом каждого сценария.
- Готово, когда: реальное окно проходит вставку, импорт файлов и drag-and-drop, Auto/explicit check, отмену, retry, детали, фильтры, clipboard, запись/повторное открытие файлов и закрытие сессии. Отдельно выполнен единичный smoke встроенного endpoint без сохранения реальных реквизитов.

### [ ] T-030. Измерить производительность и ресурсы

- Зависимости: T-029. Требования: NFR-01–NFR-05; AC-14.
- Результат: английский отчёт для release-сборки с эталонной машиной, наборами 10 000/100 000 записей, p95 реакции GUI, суммарным RSS и временем отмены.
- Готово, когда: достигнуты нормативы PRD; при необходимости устранены подтверждённые профилированием узкие места. Лимиты проверены на управляемых локальных серверах, публичный endpoint не используется для нагрузочного теста.

### [ ] T-031. Проверить приватность и устойчивость

- Зависимости: T-007, T-020, T-028, T-029. Требования: FR-12; NFR-06; AC-12, AC-14.
- Результат: проверка логов, IPC, файлов состояния и сообщений на синтетические секреты; обработка malformed/oversized ответов, файлов и отмены.
- Готово, когда: секреты отсутствуют в неразрешённых каналах; capabilities/CSP проверены; входные значения рендерятся текстом; прямой fallback отсутствует; ошибки не приводят к panic, вечной задаче или повреждению экспортируемого файла.

### [ ] T-032. Подготовить сборки и автоматические проверки

- Зависимости: T-005, T-012, T-020, T-028. Требования: NFR-07, NFR-08; AC-15, AC-16.
- Результат: CI для format/lint/typecheck/unit/integration/build, платформенные пакеты и инструкции воспроизведения.
- Готово, когда: проверки проходят на поддерживаемых runner-средах, сетевые тесты не зависят от публичных сервисов, артефакты содержат ожидаемые зависимости и контрольные суммы. Локальная сборка, опубликованный пакет и подтверждённая GUI-работа описываются раздельно.

### [ ] T-033. Проверить Windows нативно

- Зависимости: T-029, T-032. Требования: NFR-07; AC-15.
- Результат: установленная сборка и английский отчёт для заявленных Windows/архитектур.
- Готово, когда: проверены запуск, WebView, локальная протокольная матрица, TLS trust, импорт/drag-and-drop, clipboard, Unicode-пути, экспорт, отмена и удаление приложения. При недоступной Windows задача остаётся открытой.

### [ ] T-034. Проверить macOS нативно

- Зависимости: T-029, T-032. Требования: NFR-07; AC-15.
- Результат: установленная сборка и английский отчёт для заявленных macOS/архитектур.
- Готово, когда: проверены запуск, локальная протокольная матрица, TLS trust, Cmd-сочетания, системные диалоги/clipboard, Unicode-пути, экспорт и отмена. Подпись/notarization отражаются по фактическому состоянию; при недоступной macOS задача остаётся открытой.

### [ ] T-035. Подготовить первую версию к выпуску

- Результат: актуальный английский README с форматами и ограничениями, CHANGELOG, руководство проверки/экспорта, пакеты и итоговая матрица приёмки.
- Готово, когда: все обязательные критерии закрыты доказательствами; документация соответствует интерфейсу; версии пакетов согласованы; установленные артефакты проходят smoke. Результат задачи — подготовленный выпуск; публикация выполняется отдельным действием, если она запрошена.
